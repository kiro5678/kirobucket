## Installer classification

Pake's Windows WiX template declares `InstallScope="perMachine"`, uses `ProgramFiles64Folder` by default, and registers Start Menu/Desktop shortcuts. It exposes an `INSTALLDIR` property. The manifests therefore call the official MSI through elevated `msiexec /i`, override `INSTALLDIR` to the Scoop version directory, and call `msiexec /x` with the retained MSI for updates/removal. They are **Nonportable** even though their main files are inside Scoop.

The manifests deliberately omit manual `shortcuts` because Windows Installer owns the vendor shortcuts. They also omit `bin` until the Windows MSI lifecycle test verifies the installed executable path. Each package requires Microsoft Edge WebView2 Runtime.

Pake's Output Exception says Pake-built outputs need not be GPL-licensed, but it does not declare an individual license for these prebuilt wrappers. They are marked `Unknown` instead of incorrectly assuming GPL-3.0.

## Validation

- GitHub Release asset SHA-256 values were read from official release metadata.
- `.github/workflows/pake-windows-msi-test.yml` downloads and checks all 16 assets, reads MSI product metadata, installs each package to an isolated Scoop-style directory, verifies its executable and Start Menu/Desktop shortcuts, then removes it using Windows Installer.
- Scoop `/verify`, checkver, autoupdate, and the Windows lifecycle workflow must pass before merge.
